## 意图识别

收到 `/test` 后，先解析用户的输入，判断属于哪种模式：

| 用户说法示例 | 对应模式 |
|-------------|:------:|
| `/test`（无参数） | **模式 C** — 生成完整测试清单 + 逐模块指导 |
| `/test 预约流程` `/test gallery` | **模式 A** — 指定模块测试 |
| `/test 管理后台` `/test 积分` | **模式 A** — 指定功能测试 |
| `/test 记录` `/test 结果` | **模式 B** — 记录用户反馈的测试结果 |

## 模式 A：指定模块测试

1. 匹配用户输入到具体模块
2. 从 Skill.md 测试清单中提取该模块的测试项
3. 逐项引导用户操作（用小白友好话术）
4. 记录每项结果
5. 输出该模块测试小结

## 模式 B：记录测试结果

用户描述测试结果时：
- 记录通过/失败的测试项
- 对失败的项：分析原因 → 提供修复建议 → 询问是否需要帮助修复
- 对环境限制的项：标记"跳过"并说明原因

## 模式 C：完整测试

1. 输出全部测试项清单（按 P0→P3 优先级排列）
2. 从 P0 核心路径开始，逐模块引导用户测试
3. 每个模块通过后再测下一个
4. 全部完成后输出完整测试报告

---

## 小程序测试特殊说明

- 微信小程序不支持自动化单元测试框架
- 测试方式为：微信开发者工具模拟器 + 手机真机预览
- 云开发未开通时，只测试本地 Mock 数据下的功能
- 需要在真机上测试的功能：扫码预览、微信登录、图片选择、拨打电话
